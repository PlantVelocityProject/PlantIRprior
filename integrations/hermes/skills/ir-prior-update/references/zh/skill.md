## 执行边界

- 从请求或已验证元数据确定物种和筛选。project 只限制检索；只计算某项目，须先取得非空、已验证的 accession 集合。集合为空时不能省略筛选而扩大到整物种。
- 保持串行。默认所有所选物种合计每次尝试 10 个样本，resume 会再次授予原预算；用户限制累计量时须核对实际历史尝试。API 预算为 1–10，直接入口 max-samples=0 是不限制。检索默认补全 100 个 run 的预算另计。
- 记录请求/任务编号、科学 batch_id、范围、预算与回执。回执丢失或对话超时不等于停止；先查原任务，不换编号试探，活动性 unknown 时不并行启动。
- 按操作参考有限恢复；仅交付失败使用 deliver。已完成周期返回冻结结果，不处理延后样本，也不刷新交付。
- 文件存在或哈希有效不等于证据就绪。共享检查同时覆盖内容、当前科学请求与整组准入；历史准入保留未知参数。不兼容、损坏或未完成证据需要明确恢复/维护，不隐式重建。

## 科学约束

元数据来自原库：SRR/NCBI、ERR/ENA、DRR/DDBJ、CRR/NGDC。未报告字段保留 unknown，协议不明确时待核验。FASTQ 可用已验证镜像；CRR 使用实际 RemotePaths，不拼接 URL。

发布改为**仅手动触发**。各物种/参考/注释组累计 **50 个新增有效样本仅作为检查点**，不自动发布，也不是显式发布的最低数量。相对最近成功发布按规范 accession 去重，重试和重算不增加数量。普通更新只积累证据并报告 waiting/checkpoint_reached，不应用聚合贡献、不恢复待完成发布、不交付资源和网站。仅在用户明确要求发布后调用 start --publish-only，跳过检索、下载、比对和提取，样本尝试数为 0，使用完整兼容证据组，不允许 accession 筛选。待完成科学发布同样等待明确发布指令；已发布版本可按明确要求使用独立交付恢复。

普通更新不改科学设置，不初始化已有五个库，不强制发布或撤回样本，也不手工删除 FASTQ/BAM、缓存、发布或失败现场。此类操作属于单独维护。科学预览也可能创建容器运行缓存。

完整 verify-evidence 是单独、可能耗时的检查，不是日常查询。用户取消后，记录为取消而不是通过，不自动重启。
